**we are a e-commerce company and you know we have customers over the globe so we actually use multi-region deployments have you ever worked on multi-region deployments if yes can you talk about multi-region deployments and how to achieve that**

-  In the current organization we have recently set up multi-region workloads earlier we were using single region workloads because of customer needs we migrated to multi-region workloads let me explain how we did it so we had customers only from a particular region of United States earlier so we set up elastic load balancer which is a local load balancer and we have multiple replicas of the workload so requests from the elastic load balancer were routed to different availability zones so that high availability was maintained however we started you know getting customers from different regions and we saw the requirement for the **global load balancing or multi-region workloads**.

   - **Global Load Balancer**

   - A Global Load Balancer distributes user traffic across multiple regions or data centers to improve availability, performance, and fault tolerance.
   - It routes users to the nearest or healthiest application server based on factors like latency, geography, or server health.

- the global load balancing or multi-reion workloads reason was very simple customers in Australia they were facing significant latency
and this was not okay for the organization so we took couple of months to implement multi-reion or cross region workloads what we did so instead of front facing with ELB we have set up a global load balancer in AWS and we have also set up AWS cloudfront that is for CDN so what we did we implemented CDN so that static content was cached by the nearby local server so let's say there is a customer in Australia using CDN so whenever user hits the DNS of our uh website so request is sent to CDN and CDN caches a copy in the nearby region of the user static content such as images CSS, JavaScript is instantly served to the customer of course CDN only takes care of static content so we have also implemented a global load balancer so from the uh CDN the static content is served and then request goes to the global load balancer global load balancer identifies which region the request has to be routed with so apart from our workloads being deployed only in the US region we have deployed the workloads in Australia and also India where we have majority of the customers now so the global load balancer identifies which region the request has to be routed to and from that particular region request is sent to the workload through the local load balancer in the region and dynamic content is served to the load balancer in the region and dynamic content is served to the customer so we have implemented combination of CDN as well as global load balancer to serve static content as well as dynamic content to the application much faster so this way we eliminated latency right so in a nutshell we used global load balancer for the
dynamic content we deployed our workloads not in a single region but we created new kubernetes nodes in different regions where our customers are and we have deployed multiple copies of our application onto those regions through the global load balancer request is routed and through the CDN static content is served
immediately so it took us a lot of time to be honest this was almost 2 to 3 months project and we were able to successfully do it that's.

**Can you talk about cost optimization more like do you work on cost optimization on regular basis and what is your experience on it**

I use Lambda functions in AWS because majority of our infrastructure is created on AWS so I use Lambda functions i use Boto3 to interact with other AWS services i look for stale resources on AWS i identify something that is not required i run lambda functions as cron jobs and I also integrate lambda functions with cloudwatch to trigger those lambda functions on particular API events let me explain one of the cost optimization that I recently worked on this was something 6 months or 8 months back but it was very significant for the company so we were using EBS volumes very actively and we were using EBS volumes not only for the instances but also for the databases many of the EBS volumes were using GP2 the recommendation from AWS sometime last year was to go for GP3 for better performance and also for cost saving we realized we have more than 100 EBS volumes and the EBS volumes were in different regions some of them were stale some of them were active so I wrote a lambda function that looks at EBS volumes in all the regions and using this lambda function I have converted the EBS volumes from GP2 to GP3 while writing this script I have also realized there are a lot of stale EBS volumes which were not at all being used they were unmounted from the EC2 instance they were not even being used by the databases they were stale for more than 3 months so I also wrote a script to delete these stale EBS volumes if required create a snapshot and delete the stale EBS volumes so these are some of the cost optimization techniques
