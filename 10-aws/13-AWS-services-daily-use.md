**“Which AWS services do you use in your day-to-day work?”**
or
**“Which AWS services are you using in your current organization?”**

This is a very common interview question.

Many candidates get confused when answering this because AWS has more than 200 services, and every service is designed for different use cases.

As a DevOps Engineer, you may know 40–50 AWS services, so naturally you may wonder:

**“Which services should I mention in the interview?”**

This is a genuine concern, but there is a very simple solution.

---

## Always Refer to the Job Description

Before attending the interview, carefully review the job description.

The job description itself tells you what the interviewer expects from the candidate.

For example, if the job description mentions services like:

* VPC
* EC2
* ECS/EKS
* ECR
* S3
* RDS
* CodePipeline

then you should mainly talk about those services during the interview.

This keeps your answers aligned with the role and helps convince the interviewer that you are a good fit for the position.

---

## Avoid Mentioning Unrelated Services

For example, if the interview is mainly for DevOps and Cloud Engineering, there is no need to focus on services like:

* SageMaker
* Rekognition
* Lex

unless they are specifically mentioned in the job description.

The interviewer is more interested in services related to:

* Infrastructure
* CI/CD
* Containers
* Networking
* Monitoring
* Automation
* Security

So always align your answer with the technologies mentioned in the job description.

---

## Example Answer

If I were asked this question, this is how I would answer:

As part of my DevOps and Cloud role in the current organization, I work with multiple AWS services on a daily basis.

The services I use mainly depend on developer requirements and project needs.

Some of the AWS services I frequently work with are:

* EC2 for compute resources
* VPC for networking and subnet configurations
* EKS for managed Kubernetes clusters
* ECR for storing and managing container images
* S3 for object storage and backups
* RDS for managed databases
* EBS for block storage volumes
* IAM for access management and role-based permissions
* CloudWatch for monitoring and alerting
* Route 53 for DNS management

For CI/CD activities, we also use:

* AWS CodePipeline
* AWS CodeBuild
* AWS CodeDeploy

Additionally, we use Lambda functions for automation tasks and cost optimization activities.

These are the AWS services I work with most frequently in my current role.

---

## Important Interview Tip

This is a simple question, so do not overcomplicate your answer.

The safest and best approach is:

1. Read the job description carefully
2. Identify the AWS services mentioned there
3. Talk mainly about those services
4. Explain briefly how you use them in your daily work

This makes your answer more relevant and professional.

The interviewer mainly wants to check whether your experience matches the requirements of the role.
