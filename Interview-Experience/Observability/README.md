## 💡 Top Observability Interview Questions

### Q1: Metrics vs. Logs vs. Traces — when do you use each?
* **Metrics**: Aggregated numerical data measured over time intervals (CPU, memory, request rates, error rates). Best for **alerting and spotting high-level anomalies**.
* **Logs**: Timestamped event records generated by software. Best for **deep-dive root-cause debugging** of why an individual transaction failed.
* **Traces**: End-to-end request lifecycle across distributed microservices. Best for **identifying latency bottlenecks and pinpointing which microservice delayed a request**.

### Q2: Pull vs. Push Metrics Architecture
* **Pull (Prometheus)**: Central Prometheus server scrapes HTTP `/metrics` endpoints on target hosts at set scrape intervals. Provides centralized control over ingestion rates.
* **Push (Datadog Agent, CloudWatch Agent, StatsD)**: Local agent or application actively pushes metrics outbound to a central endpoint. Better for short-lived serverless workloads (AWS Lambda).
