# What Is the Difference Between Monitoring and Observability?

This is a very common observability interview question.

When an interviewer asks this question, they are trying to understand whether you know the difference between simply detecting a problem and actually diagnosing it.

---

## Monitoring

**Monitoring tells you when something is wrong with your system.**

For example:

* CPU usage is high.
* Memory usage is high.
* Disk space is running low.
* An application is down.
* Response time has increased.

Monitoring tools collect metrics and display them through dashboards. They can also trigger alerts when predefined thresholds are crossed.

### Examples of Monitoring Tools

* Prometheus
* Grafana
* Amazon CloudWatch

### Monitoring Answers Questions Like:

* Is the application healthy?
* Is CPU usage above 80%?
* Is memory utilization increasing?
* Is the service available?

---

## Observability

**Observability goes a step further and tells you why something is wrong with your system.**

If a service is down, observability helps identify the root cause.

Observability typically relies on three pillars:

### 1. Metrics

Numerical measurements such as:

* CPU utilization
* Memory usage
* Request count
* Error rate

### 2. Logs

Detailed event records generated by applications and infrastructure.

Example:

```text
Database connection timeout
```

### 3. Traces

Track requests as they move through multiple services.

Example:

```text
User Request
      |
      v
API Gateway
      |
      v
Service A
      |
      v
Database
```

Traces help identify where delays or failures occur.

---

## Monitoring vs Observability

| Monitoring                            | Observability                        |
| ------------------------------------- | ------------------------------------ |
| Tells you **when** something is wrong | Tells you **why** something is wrong |
| Focuses mainly on metrics and alerts  | Uses metrics, logs, and traces       |
| Detects problems                      | Diagnoses problems                   |
| Threshold-based                       | Root-cause analysis                  |
| Reactive alerts                       | Deep troubleshooting                 |

---

## Real-World Example

Suppose an application becomes slow.

### Monitoring Tells You:

```text
CPU Usage = 95%
Memory Usage = 80%
Response Time = 5 seconds
```

You know there is a problem.

---

### Observability Tells You:

```text
CPU Usage = 95%
       |
       v
Java Process Consuming CPU
       |
       v
Excessive Database Queries
       |
       v
Missing Index on Database Table
```

Now you know:

* Which process is causing the issue.
* Why it is consuming resources.
* What needs to be fixed.

---

## Easy Analogy: Car Dashboard vs Mechanic

### Monitoring = Car Dashboard

A car dashboard can tell you:

* Low fuel
* Engine warning light
* High engine temperature

It tells you **something is wrong**.

---

### Observability = Mechanic

A mechanic can:

* Inspect the engine
* Read diagnostic logs
* Identify the faulty component
* Explain the root cause

It tells you **why something is wrong**.

---

## Interview Answer (Short Version)

> Monitoring tells us when something is wrong with a system by using metrics, dashboards, and alerts. Observability goes a step further and helps us understand why the issue occurred by analyzing metrics, logs, and traces. In simple terms, monitoring detects problems, while observability helps diagnose and troubleshoot them.

---

## One-Line Interview Answer

> Monitoring tells you **when** a problem occurs, while observability helps you understand **why** the problem occurred by using metrics, logs, and traces.
